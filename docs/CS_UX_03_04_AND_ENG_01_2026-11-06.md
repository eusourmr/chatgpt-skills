## ENG-01: reproducing an out-of-order asynchronous search regression

**Objective:** exercise `engineering-investigator-labs` in the installed private plugin on a known synthetic JavaScript bug (stale network response overriding the newer user's query). No real user data or external APIs are required.

Open a **new conversation with CS Navigator Labs selected**. Paste the complete task:

```text
Use engineering-investigator-labs to investigate the following synthetic JavaScript bug in a mobile lodging search. Two searches run in sequence: A="Goiânia", then B="Aparecida de Goiânia". B responds in 100 ms; A responds in 900 ms. The screen incorrectly ends by showing A, even though B is the active search.

Please:
1. Identify a reproducible root cause based only on this code, separating observed/given facts from assumptions.
2. Propose a minimal patch (JS/TypeScript pseudocode is acceptable) preserving response ordering, including an appropriate loading state and error recovery.
3. Write at least two deterministic regression tests or test cases for out-of-order responses and a request failure, without a real network.
4. Address cancellation and the race between successive requests. Distinguish ignoring stale results from actually cancelling a request.
5. Mark explicitly whether you actually ran tests or edited a repository. Do not claim success based only on proposed code.

const state = { filtros: null, resultados: [], carregando: false, erro: null };

async function buscarHospedagens(filtros) {
  state.filtros = filtros;
  state.carregando = true;
  state.erro = null;
  render(state);
  try {
    const url = "/api/hospedagens?cidade=" + encodeURIComponent(filtros.cidade);
    const resposta = await fetch(url);
    if (!resposta.ok) throw new Error("Falha HTTP " + resposta.status);
    const dados = await resposta.json();
    state.resultados = dados;
  } catch (erro) {
    state.erro = String(erro);
  } finally {
    state.carregando = false;
    render(state);
  }
}
```

**Behavior rubric** (do not pre-suppose the skill's response):
1. Root cause correctly identified in cross-request effects on `resultados`, `carregando`, and `erro`, without invented source access.
2. Patch protects **every** relevant state mutation against stale requests; request sequence ID or an equivalent token acceptable; optional AbortController alone may not suffice unless handling late callbacks.
3. Test: start A, start B, resolve B, then A; final results reflect B and loading remains correct.
4. Test: fail stale A after B succeeds, and fail active B, distinguishing errors and preserving query state. No real network call required.
5. Model explicitly says whether it executed tests/patch. `proposed` must not be labeled `tested`.

A correct plan qualifies a **conversational debugging output**. Real engineering qualification also needs executable tests in a controlled JS runtime or repository and record of the actual host invocation and code under test.
