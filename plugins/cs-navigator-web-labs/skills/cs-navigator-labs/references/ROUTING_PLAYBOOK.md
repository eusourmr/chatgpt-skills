# Universal Beta — compact routing playbook

| User goal | Default | Escalation gate | Evidence required |
| --- | --- | --- | --- |
| Simple fact or short rewrite | Native ChatGPT | None | No specialist or registry action |
| UX, substantive code debugging, ABNT, academic source integrity, precision text edits | Installed specialist if available and material | Host skill listing + actual SKILL.md read | Source path/URI read and explicit limits |
| Which skill or plugin covers my goal? | Read-only registry discovery | Host has MCP tool and policy permits call | Returned tool name, metadata evidence state |
| Live operational action or private source needed | Explicitly permitted app/action | User authorization and smallest scope | Tool receipt + result, not merely a plan |

## Discovery-to-use ladder

1. Registry listed a capability — *source/discovery only*.
2. Plugin/package exists — *available source*.
3. Host lists skill or MCP — *host-visible*.
4. Skill instructions read or MCP called — *observed invocation with exact URI/tool*.
5. Method applied and output checked — *behavioral review*.
6. Real app/user outcome verified — *field evidence*.

Never advance a stage without its own evidence. Do not equate a successful CI run for an isolated fixture with deployed behavior. Use the stable core and approved permissions; never auto-install a registry result.

## Offline and failure handling

Registry missing/timeouts/empty: proceed natively without claiming a cached or fresh result. If a specialist is known but unreadable, provide a native answer with caveat instead of pretending activation. For sensitive domains, do not move private content into an optional registry query: send a generic de-identified goal only if lookup materially improves it.
